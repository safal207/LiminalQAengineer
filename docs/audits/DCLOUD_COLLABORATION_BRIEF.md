# DCloud · предложение пилотного QA-аудита

> Независимый outside-in обзор публичного цифрового контура.  
> Evidence-only: документ не является претензией, security report или оценкой внутренних процессов DCloud.

## Кратко

В рамках ограниченного публичного аудита были проверены семь страниц DCloud в двух браузерных профилях: desktop и mobile.

Проверка выполнялась только через естественную навигацию по общедоступным HTTPS-страницам. Авторизация, отправка форм, активное security-тестирование, нагрузка, fuzzing, прямое тестирование API и внешнее раскрытие не выполнялись.

Технический контур аудита воспроизводим: для наблюдений сохраняются URL, HTTP-статус, видимый текст, ссылки, browser screenshots, console/network summaries и SHA-256 evidence.

## Три приоритетных наблюдения

### 1. Конфликт актуальной и устаревшей контактной информации

На основном домене одновременно доступны текущая контактная страница и старая публичная страница с другим email, телефоном, доменом и датировкой.

**Потенциальный эффект:** кандидат или клиент может использовать устаревший канал связи, не получить ответ и прекратить взаимодействие.

### 2. Смешение QA- и developer-сценариев в вакансии QA

На странице QA-вакансии одновременно присутствуют формулировки о рабочем графике, почасовой оплате, live refactoring / live coding и обращение к junior/middle developers.

**Потенциальный эффект:** сильный QA-кандидат может неверно понять роль, формат интервью или ожидания по нагрузке и отказаться от отклика.

### 3. Повторное использование описания Backend/Fullstack-роли

В публичном описании команды несколько разных специализаций используют одинаковый текст Backend/Fullstack Team Lead.

**Потенциальный эффект:** публичная витрина слабее демонстрирует реальную экспертизу команды и создаёт ощущение незавершённого контентного шаблона.

## Дополнительные сигналы

- На основном домене доступна старая шаблонная страница с нерелевантным содержанием, повторяющимися сотрудниками и шаблонными вакансиями.
- В английской версии присутствуют устойчивые spelling, grammar и semantic localization signals.
- На отдельных страницах наблюдаются accessibility- и content-structure сигналы, требующие отдельной проверки с согласованным scope.

## Что уже подтверждено

Наблюдения воспроизведены на desktop и mobile для публичных страниц без anti-bot варианта и без выхода за домен `dcloud.tech`.

Это позволяет считать их подтверждёнными кандидатами на продуктовые дефекты публичного контура, но не доказывает внутреннюю техническую причину и не измеряет фактическую потерю конверсии.

```yaml
public_reproduction: CONFIRMED
root_cause: HYPOTHESIS_ONLY
business_impact: PLAUSIBLE_NOT_MEASURED
security_vulnerability: NOT_CLAIMED
external_disclosure: NOT_PERFORMED
```

## Предлагаемый пилот

### Формат

Короткий пилотный аудит одного публичного пользовательского пути, например:

- кандидат → вакансия → понимание роли → отклик;
- потенциальный клиент → услуги → доверие → контакт;
- англоязычный клиент → international landing → подтверждение экспертизы → заявка.

### В пилот входит

1. Карта пользовательского пути и точек потери доверия.
2. QA-проверка desktop/mobile состояний.
3. Системная карта источников контента и противоречий.
4. Бизнес-приоритизация findings по влиянию и стоимости исправления.
5. Воспроизводимый evidence pack со скриншотами и точными условиями наблюдения.
6. Короткий итоговый созвон с рекомендациями и следующими шагами.

### Ожидаемый результат

- 5–10 проверенных findings без шума и неподтверждённых утверждений;
- разделение фактов, гипотез и бизнес-рисков;
- приоритетный remediation backlog;
- понятная основа для решения о более широком сотрудничестве.

## Принципы работы

- доказательства до вывода;
- публичные дефекты не выдаются за security-уязвимости;
- root cause не заявляется без внутренней проверки или контрфактуального теста;
- автоматический verdict не заменяет человеческое решение;
- никакие изменения, публикации или внешние действия не выполняются без согласования.

## Предлагаемый следующий шаг

15–20-минутный созвон, на котором можно показать три наиболее существенных наблюдения, проверить их актуальность вместе с DCloud и согласовать границы небольшого пилота.
